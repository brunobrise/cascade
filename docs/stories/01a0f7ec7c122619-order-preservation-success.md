# Window Order Preservation on Lifecycle Events Success Story

## 1. Context

During continuous window management, users organize active windows into a mental or spatial layout (e.g. Editor in Slot 0, Browser in Slot 1, Terminal in Slot 2). 

Previously, when an automatic window lifecycle event occurred (such as opening a new window, resizing, minimizing, or closing a window), Cascade re-sorted the entire set of windows based on momentary WindowServer MRU Z-order. Furthermore, if Z-restacking was enabled, Cascade raised all windows in reverse sequence, altering user focus and shuffling existing windows into different slots.

## 2. Intended Outcome

When automatic window lifecycle events fire (new window, window resize, window minimize, or window close):
1. **Zero Order Disruption:** The established sequence of existing windows must remain unchanged. No existing window may swap slots with another.
2. **Pure Size Adjustment:** Only window dimensions $(w, h)$ and their corresponding cascade offsets $((i)\delta, (i)\delta)$ adjust to fit the updated active window count $N$.
3. **Focus Stability:** Z-order restacking (`kAXRaiseAction`) is suppressed during event-driven updates, preventing focus theft from the currently active application.
4. **Loop Prevention:** Watcher notifications generated by Cascade's own layout movements are cleanly suppressed to prevent infinite feedback cascades.

## 3. What Worked and Why

1. **Set Partitioning Algorithm:**
   - Active windows are partitioned into an established sequence $E = S_{curr} \cap S_{prev}$ and newly appeared windows $N = S_{curr} \setminus S_{prev}$.
   - $E$ preserves the exact sequence indices from $S_{prev}$.
   - Newly opened windows $N$ are appended at the tail of the cascade without shifting existing windows: $S_{new} = E \mathbin{\Vert} N$.
2. **Robust Multi-Attribute Window Matching:**
   - Cascade windows match across events using `CFEqual(axRef1, axRef2)` first, with fallback to stable process identifier `pid` and title/appName.
3. **Execution Suppression Guard:**
   - Added `performWithoutTriggering:` in `WindowWatcher`. While Cascade executes position and size attributes via the Accessibility API, watcher debounce timers are cleared and suppressed, eliminating recursive event loops.
4. **Selective Z-Restack:**
   - Manual cascades (`Option + Command + C` or menu selection) execute Z-restack according to user preference, while automatic event-driven cascades strictly set `restackZ: NO`.

## 4. Empirical Evidence

- **Unit Test Suite (`tests/test_engine.m`):**
  - `testOrderPreservationOnWindowClose`: Confirmed that closing an intermediate window preserves the exact sequence of remaining windows and recalculates expanded dimensions ($W - \delta$).
  - `testOrderPreservationOnNewWindow`: Confirmed that opening a new frontmost window leaves existing window slots and order untouched, appending the new window at the tail.
  - `testOrderPreservationOnResize`: Confirmed that user resize events retain existing slot ordering while snapping windows back to uniform cascade proportions.
- **Watcher Suppression (`tests/test_watcher.m`):**
  - `performWithoutTriggering`: Asserted that notifications emitted during internal layout execution are suppressed.

## 5. Reusable Engineering Pattern

When coordinating automatic window tiling or cascading on macOS:
- Separate **user-initiated baseline reordering** from **event-driven geometry maintenance**.
- Treat the active window list as an ordered sequence where updates perform set operations ($E \mathbin{\Vert} N$) rather than re-sorting.
- Always guard layout setters with execution suppression flags to prevent recursive AX observer notifications.
